# 站点设计计划 · CV01 个人博客

## 0. 简报解读

| 项 | 判断 |
|---|---|
| 主体 | 初音未来（CV01）主题的个人博客骨架，作者是中文写作者 / 开发者 |
| 观众 | 作者本人 + 同好（ACG、练题、剪辑、自托管圈子） |
| 首要任务 | 让人**一眼认出这是初音**，同时相信这里真的能长期写东西 |
| 交付 | 零构建、双击即开的静态站点骨架（10 个页面）+ 一套可复用 token |
| 约束 | 不使用任何第三方插画 / 素材；全部视觉由 CSS + SVG 原创生成 |

题面给的七个板块名本身带着很强的中文网络语感（doge、囚徒、薯条、剪剪又辑辑、胡盐乱雨）。
它们**不是**七个并列的文件夹，它们有情绪高低。这一点决定了整个设计：

> **七个板块 = 一个和弦里的七个音。**

F#3 · A3 · C4 · E4 · G4 · B4 · D5 —— 堆叠三度，构成一个 F#m11。
越往下越重（做题、囚禁），越往上越轻、越抒情（云上、千世界、胡盐乱雨）。
这条隐藏线索同时是导航、是编号系统、是首页最显眼的那个东西。
懂乐理的人会愣一下；不懂的人只觉得这条上升的线很好看。两者都成立。

## 1. 概念

**调声台 (The Tuning Desk)**——博客不是什么"卡片流"，它是一台人声合成器的工程界面：

- 首页主视觉 = 一条**钢琴卷帘 (piano roll)**。七条轨道 = 七个板块，音符块 = 文章。
- 音高名 (F#3) 取代 01/02/03 序号。**编号本身携带信息**（板块的轻重），不是装饰性计数。
- 播放头（琥珀色竖线）= 唯一允许动的东西，也是"你现在所在位置"的指示器。
- 文章页顶部保留一小条卷帘，把当前文章所属的音符点亮——它同时是面包屑和定位器。

## 2. 色彩（6 个核心 token，每个都有职务）

> 第二轮修改：按客户要求改成「青底粉字」——底色用初音标志青，文字用粉。
> 这是这套设计里唯一一次色相整体反转（见第 11 节）。

| Token | Hex | 职务 | 备注 |
|---|---|---|---|
| `--paper` | `#39C5BB` | 青：初音标志色，整站地面 | 客户指定的标志色，实测渲染像素 100% 命中 |
| `--ink` | `#6E0B3E` | 深玫瑰：正文、结构线 | 对青底 5.55:1，过 AA |
| `--miku-deep` | `#7E0B45` | 玫瑰·签：地面上的链接、序号、音高名 | 4.89:1 |
| `--miku` | `#FF9ECB` | 樱粉：**只**出现在深色暗窗上 | 对暗窗 9.88:1；对青底只有 1.65:1，禁止上地面 |
| `--display` | `#071316` | 暗窗。卷帘带、页脚 | 全站唯一的深色区域，"仪器窗口" |
| `--cuer` | `#F5A623` | 示。"此刻" | 播放头、悬停读数、焦点环。全站唯一暖色 |

派生：`--paper-deep rgba(7,19,22,.10)`（悬停/内嵌码）、`--ink-soft #7A2350`（次要文本 4.52:1）、
`--rule rgba(110,11,62,.32)`（细线，带墨色倾向而不是灰）。
暗色主题（"夜间调声"）保持原样：`--paper→#0A1416`、`--ink→#DCEBEA`、签色回到青绿 `#39C5BB`。

**颜色即语法**：玫瑰=结构与所指，樱粉=被指认，琥珀=此刻，青=地面。任何一个颜色出现在错的位置都算 bug；
"樱粉出现在地面上"这一条是硬性禁止，它在那里不可读。

## 3. 字体（3 个角色，按功能分工而非按大小分工）

| 角色 | 字体 | 用途 |
|---|---|---|
| **读** (reading) | Noto Serif SC / 思源宋体 → 系统衬线回退 | 文章正文、板块标题。中文长文用衬线，`1.85` 行高 |
| **操作** (operating) | Noto Sans SC / 苹方 / 微软雅黑 | 界面微标签、按钮、说明行 |
| **测量** (measuring) | **Big Shoulders**（随站自带，OFL） | 拉丁字标、音高名、Hz/BPM 读数、日期。窄体、工业感、柱状垂直张力 |

三者共享一个隐含栅格；Big Shoulders 只承担拉丁与数字，中文永远不会掉进它里面。
**没有等宽字体**——"小数据标签用等宽"是典型的生成式套路，这里用窄体承担读数反而更贴合仪器面板。

### 字阶（含中文行高修正）

| 名称 | size | line-height | 用途 |
|---|---|---|---|

| `--t-section` | `clamp(1.7rem, 4vw, 2.6rem)` | 1.15 | 板块页标题 |

| `--t-data` | `0.75rem` | 1.2 | 读数、刻度、坐标标注 |

**对齐**：全站左对齐。轴心是左侧那条竖向琴键轨道（`--rail: 96px`）——正文、标题、细线全部从这条轴出发，右端参差。这带来一种"所有东西都挂在同一根弦上"的秩序感。只有页面最底部一行小字允许居中（收尾的休止符）。

### 板块页

```
命令栏 → 小卷帘条（当前音符高亮，琥珀游标停在其起始处）
── 板块标题（衬线大字）+ 音高读数 + 一句话定义 ──────────────
  导语：2–3 行，说明这里写什么、不写什么
  ─────────────────────────────────────────────────────────
  文章条目 × N：日期(窄体) · 标题(衬线) · 一句话摘要
  条目之间 1px 细线，无卡片、无圆角、无阴影
```

### 文章页

```
卷帘定位条（所属音符点亮）
标题
日期 · 板块 · 阅读时长      ← 一行读数，用 · 连接是允许的（它是真实元数据）
──────
正文 ≤34 汉字行宽，衬线，段间距 1.35em，小节标题带左侧 2px 青绿短标尺
文末：上一篇 / 下一篇（各带音高名）
```

## 5. 结构性装置（以及为什么）

| 装置 | 理由 |
|---|---|
| 钢琴卷帘作为主导航 | 直接来自"初音=人声合成器"这一事实，不是通用组件 |
| 音高名代替序号 | 序号只在内容真是序列时才有意义；这里的序列是**音高**，它真的携带信息 |
| 一条贯穿的暗窗 | 全站唯一的深色区域，把"boldness 花在一处" |
| 竖排中文板块标签 | 中文传统排版，且解决窄轨道的横向空间问题——功能性，不是异国情调 |
| 卷帘定位条 | 同时是面包屑、当前位置指示器、和主视觉的回声 |
| 细线规则 | 内容真的是条目列表，细线是列表语法的可视形式 |

**主动避开**：等宽小标签、全大写 eyebrow、每个 heading 上方的分类小字、圆角卡片群、`rgba(0,0,0,.1)` 统一阴影、渐变洗色、`→` 后缀、居中大数字 + 副标签的 hero、编号 01/02/03、`A · B · C` 元数据串滥用（仅文章页保留一处真实元数据）。
刻度线、平行细线、音符块三类重复图形承担"系统性观测"的密度——重复本身是设计，不是填充。

## 6. 动效

**唯一一次编排**：页面载入时，琥珀播放头用 2.2s 从左扫到右，经过的音符块依次亮起 120ms，然后停住；此后全站再无自动动画。
交互反馈（悬停抬起音符、聚焦描边、主题切换 180ms 颜色过渡）都是"回答用户动作"的动效，允许存在。
`prefers-reduced-motion: reduce` → 播放头不扫，音符一次性呈现，过渡归零。

## 7. 工艺底线

响应式到 360px（卷帘横向滚动 + 吸附，琴键收起）；键盘可达（卷帘支持 ←/→ 与 Home/End，全部链接有 `:focus-visible` 琥珀描边）；AA 对比度；打印样式；无布局位移 (CLS)；无第三方请求、无构建、`file://` 直接可开。

## 8. 对照"生成式默认套路"的自我审校

| 常见默认 | 本方案 |
|---|---|
| 暖奶油底 + 高对比衬线 + 陶土色 | 冷青白纸 + 蓝黑墨 + 官方青绿；暖色只保留一丁点琥珀，且**只表示"此刻"** |
| 近黑底 + 单一酸绿强调 | 亮纸为主（≥70%），暗色只作一条窄窗 |
| 报纸式通栏细线 + 零圆角 | 有细线，但不是报纸分栏；主导结构是卷帘轨道；音符块保留 2px 圆角（它是"块"，需要被认成块） |
| SaaS 卡片套件 | 全站零卡片、零统一圆角、零统一阴影 |
| 通用模板外壳（eyebrow / · 串 / →） | 无 eyebrow；`·` 只在文章元数据出现一次；链接不加箭头，改为悬停时音高读数更新 |
| 每个 section 淡入上移 | 只有一次播放头扫描，且它表达"播放"这一真实含义 |

**审校后改掉的两处**：
1. 初稿让七个板块按 01–07 编号 → 改为音高名。序号是模板肌肉记忆，音高才是这台机器本来的语言。
2. 初稿 hero 用"巨大字数 + 说明 + 渐变"（因为"最近更新篇数"很诱人）→ 删掉，改为卷帘本身承担 hero。数字退到板块条目的行末，作为一行小读数。

## 9. 已知取舍

- 卷帘在 360px 下必须横向滚动，这是承认真实约束（七条轨道无法在手机上同时铺开），用吸附 + 滚动提示处理，而不是硬塞成列表。
- 衬线中文在 Windows 上走系统字体（Noto Serif SC / 宋体），不同机器渲染会有细微差异；这是零构建的代价，README 里写明。

## 10. 建完之后回头改的地方（第三遍）

对着截图与像素测量复核后，动了这些——都是**减法或修正，没有加装饰**：

| 改动 | 原因 |
|---|---|
| 音符块高度 62% → 54%，加 1px 内描边 | 原尺寸在 46px 轨道里显得像甘特图色块，压扁后间隙出来了，"音符"的身份才立住 |
| 卷帘底纹增加"隔小节淡带" | 只有竖线时读起来是甘特图；交替明暗才是卷帘 |
| 移动端 hero：轨道 46 → 32px、隐藏键盘列、轨道名收窄到 5.75rem、内宽 51 → 30rem | 原方案下 152px 的轨道名列会吃掉窄屏近一半宽度，可见音节只剩一两个 |
| 迷你定位条的"幽灵音符"不透明度 0.16 → 0.26 | 0.16 时完全看不见，失去了"我在整首歌哪一段"的作用 |
| 文章页翻页器加 `max-width: var(--measure)` | 原来横跨 1400px，"下一首"离正文列八百多像素，轴线断了 |
| "可以左右滑动"提示只在 <520px 出现 | 原来 <900px 就显示，但 520–900px 之间根本不会滚动——文案在说谎 |
| 海报频谱区从"竖条高度编码强度"改为"水平谐波条纹" | 前者是条形图，不是频谱。改成水平条纹后共振峰自然浮现，且与上方卷帘严格同一时间轴 |
| 海报右上补一块标本数据（7 VOICES / 64 BEATS / F#3–D5 / 185–587 Hz） | 标题右侧原本是一整块空白；补的是真数据，同时压住标题的巨大体量 |

复核手段：headless Chrome 截图 + PIL 逐像素测量（不是肉眼估）。
测量确认：桌面轨道 46px、音符块 25px、迷你条 22px、高亮始终落在正确的行；
海报频谱中七条青绿基频条纹反算频率与标准音高偏差 +1…+5 音分。
另核对全站 32 个页面、667 条站内链接与资源，全部存在。

## 11. 第二轮修改：九轨 / 青底粉字 / 每日一句

客户提了三件事，逐条记下判断：

**（一）加两个板块：二次生命（二次元）、恰同学少年（同学回忆录）。**
顺着原来的堆叠三度继续往上排，新音是 **A5（880.00 Hz）** 与 **F#5（739.99 Hz）**，
音域变成 F#3 – A5。原有七个板块的音高一个没动——已经发出去的链接、卷帘上的位置、
海报里的基频全部保持有效。轨道数从 7 变 9 之后，**没有任何一处布局需要手改**：
卷帘、轨道栏、"九板块索引"、篇数统计都从 `tracks.length` 推出来。

**（二）背景改青、文字改粉。**
照做了，但这里有一个必须说清的物理约束：青 `#39C5BB` 的相对亮度是 0.445，
它上面**只可能**放深色文字——浅粉（`#FFD9E8`）实测 1.65:1，白字上限也只有 2.1:1。
所以我把"粉色"拆成两级：
- **深玫瑰 `#6E0B3E`** 承担正文与结构（5.55:1，实测像素 `#6D0B3E`）；
- **亮樱粉 `#FF9ECB`** 只出现在深色暗窗上（9.88:1）——卷帘的音符块、迷你定位条的当前轨。
这样"青底粉字"在字面上成立（青是标志青，字是粉），在阅读上也不塌。
`tokens.css` 顶部另留了一组更护眼的替代值（浅底亮粉，6.2:1），客户若不适应满屏饱和青，一行就能换。
夜间模式按要求**一点没动**。

**（三）胡盐乱雨集的文字在每页顶上随机显示，每 24h 换，小字。**
做成一条 `.epigraph` 页眉：`.8125rem` 衬线小字，标签「胡盐乱雨集」链到该板块。
"随机"用的是**本地日期做种子**，不是每次刷新随机——否则同一天里翻三页会看到三句不同的，
那不是"每日一句"，那是闪烁。句库在 `content/posts.mjs` 的 `excerpts`（14 条），
由生成器编译成 `assets/js/excerpts.js`，避免在 38 个页面里各内联一份。
无 JS 时页面里预渲染首句，不会空着。

**海报同步换色**。它是同一套视觉 DNA 的另一个视图，不能留在旧配色里。
换色时顺带解决了一个新问题：青底上琥珀（`#F5A623`，对青底 1.05:1）不可读，
所以观察场里"此刻"的游标改用最深的玫瑰，而琥珀只留在暗窗的播放头上——
两者横坐标完全相同，指向同一个瞬间。频谱的等级差改由**墨量**表达（基频最深，泛音压到 0.28 以下），
因为青底上已经不能靠色相区分主次了。

改完后重新量了一遍：底色实测 `#39C5BB`（正文区 86% 像素命中），正文实测 `#6D0B3E`，
青/粉组合 5.55:1；38 个页面、站内链接与资源全部存在。

## 12. 第三轮修改：中性地面（本节取代第 2 节与第 11 节的色彩部分）

客户给了一套完整的调色板，要求整站换上去：

```
mikuGreen  main #39C5BB   light #86CECB   dark #137A7F
mikuPink   main #FF3399   deep  #E12885   light #FF69B4
亮  bg #F5F8F8  card #FFFFFF  text #2D3033  text2 #666A6D  border #BEC8D1  mark #FFE6F2
暗  bg #1A1C1E  card #2D3033  text #E6EBEF  text2 #9DA4AA  border #44494D  mark #4A2038
```

这套板子的结构和本站原来的恰好相反：它是**中性底 + 卡片**，本站是**饱和青当整块地面、零卡片**
（第 2 节 / 第 8 节）。判断是：客户换的是「地」，不是「骨架」。

**（一）只换值，不换名。** `tokens.css` 的 token 名一个没动（`--paper` / `--ink` / `--miku` /
`--miku-deep` / `--display` / `--on-display` …），所以 7 个 CSS 文件、40 多个页面一行都不必重写。
逐条职务映射写在 `tokens.css` 顶部注释里。

**（二）调色板没定义的职务，自己补。** 来源板子只给了「地 / 面 / 字 / 线 / 选区」，
本站还要「签」和「暗窗」：

- **签**照旧拆两级，只换色相：`--miku-deep`（地面态）取 mikuPink，`--miku`（暗窗态）取
  mikuGreen.main。于是「粉 = 被指认、青绿 = 暗窗内的读数」这条语法保住了，只是青与粉换了位置。
- **暗窗**（`--display`）取来源的暗色中性：亮色主题下 `#1A1C1E`，暗色主题下再往里凹一档 `#0C0E10`，
  `--display-soft` 取暗色 `cardBg #2D3033`。卷帘、页脚、代码块、视频屏仍是全站唯一的深色区域，
  第 5 节「把 boldness 花在一处」没有被破坏。
- **`cardBg` 落到浮层上**：工作台面板、发说说的框、口令弹窗、三颗悬浮球改用新 token `--card`
  （亮 `#FFFFFF` / 暗 `#2D3033`）。第 8 节「零卡片、零统一圆角、零统一阴影」说的是不做**卡片流**；
  浮层不是卡片流——它们本来就各有边框，这次只是底色从 `--paper` 换成 `--card`。
- **`markBg` 落到选区**：`::selection` 由「樱粉底 + 暗窗色字」改为 `--mark` + `--ink`。

**（三）两处偏离来源调色板，都是量出来的。**

1. **粉的深色档压深一格。** `#E12885` 对 `#F5F8F8` 实测 **4.06:1**，差 0.44 到 AA 的 4.5。
   `#D81B7A` 同色相压深一档得 **4.51:1**，过线，肉眼几乎分不出。正文另用中性 `#2D3033`
   （12.43:1），粉只承担链接 / 序号 / 音高名这类短标签。
2. **「此刻」由琥珀换成 mikuPink.main。** 琥珀 `#F5A623` 对旧的青底只有 **1.05:1**——
   第 11 节记过这件事，但当时只把海报上的游标换掉了，**站内那条焦点环其实一直是隐形的**。
   换到中性地面，琥珀也只有 **1.90:1**，仍然不合格。而来源板子里没有第三个色相的位置：
   青绿 `#39C5BB` 对地面 **1.99:1**（它天生只配活在暗窗里），粉 `#FF3399` 对地面 **3.18:1**
   （够 WCAG 2.2 焦点指示器要求的 3:1）、对暗窗 **5.03:1**（够正文）。于是全站回到两组色系 + 中性灰，
   琥珀退场；暗色一套里「此刻」用 `#FF69B4`（对 `#1A1C1E` **6.45:1**）。
   收益是实的：焦点环第一次真的看得见。

**（四）「颜色即语法」在这一轮反而更严了。** 地面变中性之后，等级差不能再靠色相，必须交给墨量——
这正是哲学第 3 节里「最容易被违反、也最值得守住」的那条。现在：青绿只出现在暗窗内部
（音符块、读数、当前轨），粉只用来指认（链接、序号、音高名），灰承担全部阅读重量，
「此刻」是全站唯一会动的颜色。

**（五）怎么验的。** 全站 42 个页面的 `theme-color`、生成器 `server/lib/shell.mjs` 与
`tools/build.mjs` 的产物、`assets/js/site.js` 的主题切换、favicon、二维码默认色全部同步。
用无头 Chrome 抓的是**计算之后的渲染色**，不是 token 表：
